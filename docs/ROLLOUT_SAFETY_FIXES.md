# Rollout notes for the safety fixes

1. Back up the database and validate restoration in an isolated environment. Apply both new migrations before deploying this API. The second migration copies historical incident/contact acknowledgements into `GuardianAcknowledgement`. Delivery outcomes previously overwritten by ACKNOWLEDGED can only be restored from surviving sent/delivered/failed timestamps; missing proof is marked SKIPPED with an explanatory detail. It cannot recover destroyed history.
2. Set `PUBLIC_WEB_URL` explicitly to the HTTPS origin hosting `/room/`. Production startup requires it; CORS ordering no longer selects room links. Set an independent `MFA_ENCRYPTION_KEY` of at least 32 characters. If existing MFA secrets were sealed using the JWT key, rewrap them in a maintenance window with `MFA_LEGACY_ENCRYPTION_KEY` and the new `MFA_ENCRYPTION_KEY` supplied by the secret manager: `node --env-file=../../.env --import tsx scripts/rotate-mfa-key.ts` from `services/api`. Back up the old encryption key until recovery has been verified; never put key values in command arguments or logs.
3. Review Guardian escalation timing (`GUARDIAN_ESCALATION_DELAY_SECONDS`, default 30, bounded 5–300 seconds). Durable outbox stages are ordered recipient priority, then the mutually permitted PUSH, SMS, EMAIL channels. Any incident/contact acknowledgement stops subsequent escalation. After the final wait without acknowledgement, monitoring is escalated. Provider submissions have at-least-once semantics: a crash after provider acceptance and before recording success can duplicate a message. Lease renewal and deduplicated stage scheduling limit duplicate processing, but providers do not offer a shared transaction with this database.
4. Android database version 5 preserves legacy evidence rows, adds capture metadata and an encrypted tracking outbox. Each new capture has its own UUID, ordered chunks, original size/hash and capture time. Only complete hash-verified captures are playable through the range endpoint. Historical chunk groups cannot be inferred safely; legacy MP4 chunks remain marked as ungrouped.
5. Tracking rows store UUID, encrypted payload, retry deadline and dead-letter state. Precise coordinates and target IDs are inside the Keystore-encrypted payload. There is no sample-count truncation. Terminal target failures stop that target; sample conflicts dead-letter only the individual sample. Transient failures retry with exponential backoff. Legacy plaintext rows with no recorded time migrate as encrypted dead letters labelled UNKNOWN_TIME; no GPS time is invented. Room migration/automated builds do not establish real OEM reboot/network durability.
6. Set `ROUTER_URL` to an approved OSRM-compatible `/route/v1/driving` endpoint before relying on DRIVE/RIDE corridor alerts. Those modes use the stored routed polyline; if routing is unavailable, they report ROUTE_UNAVAILABLE and do not apply a misleading straight-line road corridor. Existing active DRIVE/RIDE sessions without a polyline must be restarted. Set `MAP_TILE_URL` to match the web build's approved tile template for independent tile health checks.
7. Optional tracing exports HTTP/Nest spans to the private OTLP collector. Room capability routes and coordinate-bearing routing/geocoding calls are excluded. Validate collection, privacy controls and cross-service propagation in staging before claiming tracing is operational.
8. Source CI uploads a clearly labelled debug APK. The separate signed-release workflow fails without the production Firebase/API/keystore settings, an owner-signed v* tag and the signing public key. It verifies APK signing, creates APK/AAB checksums and build provenance. This session has no owner signing material and has not produced a production-signed release. Run the hosted App Links verifier with the real signing fingerprint, and complete the external validation gates before launch.

The single-host Compose deployment is still a pilot topology. The Kubernetes candidate documents an external multi-zone data-service path; deploying and failure-testing it remains an infrastructure-owner action.
